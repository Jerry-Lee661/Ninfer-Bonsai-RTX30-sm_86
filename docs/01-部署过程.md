# 部署过程与踩坑记录（RTX 3080 Ti / sm_86）

按时间顺序记录从零到跑通的过程，以及每个坑的定位方式。数字来自本机实测（400W 功耗墙，
单请求，贪心）。

## 1. 选型

- 引擎：[iamwavecut/ninfer-all](https://github.com/iamwavecut/ninfer-all)。它是
  Don-Chad/ninfer-3090 一系的合并线，支持 sm_86/89/120a，含三元（ternary）内核与投机头。
- 工件：`WaveCut/Ternary-Bonsai-2-27B-NInfer-v3`（9.52 GB）。它是把 Prism 的
  `Ternary-Bonsai-2-27B-PQ2_0.gguf` 用 ninfer-v3 转换器重编码为自家容器（t2_g128_fp16，
  2.125 bit/权重），并把 DFlash2 drafter、MTP 头、proposal head、视觉塔一起打包。
  下载走镜像站即可，国内直连 HuggingFace 往往不通。

## 2. 构建（Windows + MSVC + CUDA 12.8）

```bat
call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"
set CUDA_DIR=C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8
cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release ^
      -DCMAKE_CUDA_ARCHITECTURES=86 -DCMAKE_CUDA_COMPILER="%CUDA_DIR%\bin\nvcc.exe" ^
      -DNINFER_BUILD_APPS=ON -DNINFER_DISABLE_MEDIA=ON
cmake --build build -j 24
```

坑：

- **MSVC C1061（块嵌套太深）**：`serve_options.cpp` 的 `else if` 长链会触发。规避方式是把链
  摊平成独立 `if`，**注意保持 `for` 循环的闭合位置**（见 [patches/README.md](../patches/README.md)
  里那次摊平留下的教训）。
- `-DNINFER_DISABLE_MEDIA=ON` 可以省掉 FFMPEG/CURL 依赖，纯文本部署足够。
- 构建产物较大（约 1.3 GB 的 exe），磁盘留够空间。

## 3. 部署命令

```bat
ninfer-serve.exe Ternary-Bonsai-2-27B.ninfer ^
  --port 8299 --model-id bonsai2-27b --no-thinking ^
  --spec mtp --draft-tokens 2 --host 127.0.0.1
```

注意事项：

- **旗标顺序**：在我们修复前的二进制上，`--host` 之后的旗标会被吞掉（实际是"只解析第一个
  旗标"这个更严重的缺陷）。修复后顺序不再敏感，但排查旧二进制时先查这一点。
- **数学验证**：起服日志里的 `loading weights` 体积是硬指标。带 MTP 是 7.12 GiB，带
  DFlash2 是 7.99 GiB，无投机是 6.70 GiB。数字不对就是旗标没生效。
- **投机是否真在跑**：请求结束后 `GET /stats`（主端口也有这个路由），看
  `counters.decode_rounds` 与 `committed_decode_tokens` 的比值；恒等于 1.0 说明每轮只出一个
  token，投机没生效。

## 4. 完整的坑清单

| 现象 | 根因 | 处理 |
|---|---|---|
| `--spec` 等旗标静默无效 | 解析链被包进 for 循环且 `return` 在循环内（本轮修复，见 patches/） | 用本仓的 `serve_options.cpp` 覆盖后重建 |
| 加了 `--spec` 但吞吐与不加一样 | 同上 | 同上 |
| `/v1/chat/completions` 报 `model_not_found` | 请求体里的 `model` 字段与 `--model-id` 不一致 | 请求体里写 `--model-id` 的值 |
| 中文负载投机收益远小于英文 | DFlash2/MTP 的投机头对英文与代码更有效，属模型特性 | 中文场景把 drafts 降到 2，或接受收益变小 |
| 绝对吞吐低且抖动大 | 同卡上还有别的推理进程（如另一个 llama-server）在抢资源 | 基准测量时保持 GPU 空闲，记录 clock 与功耗 |
| msys/Git Bash 下 curl 报路径错 | 路径被 MSYS 转换（例如 `/stats` 变成 `C:/Program Files/Git/stats`） | 加 `MSYS_NO_PATHCONV=1`，或用 Windows 风格路径 |

## 5. 复现我们的数字需要满足的条件

- 单请求、贪心（`temperature=0`）、无并发。
- GPU 空闲（`nvidia-smi` 利用率低于 10%），功耗墙 400W，记录 `clocks.sm` 与 `power.draw`。
- 使用同一工件与同一引擎修订；投机深度按负载选择（英文 5 drafts，中文 2 drafts）。
